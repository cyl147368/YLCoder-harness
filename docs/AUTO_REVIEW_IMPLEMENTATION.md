# 分层自动审核实现计划

本次实现将简单查询与模型分类分离，减少无效请求和重复确认。

1. 基础目录、工作区、文件名和受支持的正文查询使用 Java 原生受限执行，不依赖 `find`、`ls`、`rg`、`where` 或 `head` 的安装。
2. Git 查询先检查仓库、配置、程序身份；普通状态/分支走本地快速路径，清理预览等剩余受限操作交给无执行工具的模型分类器。
   无 pathspec 的本地 `git diff` 在审批阶段不扫描整个工作区，检查 Git 仓库元数据与配置；显式 pathspec 才检查目标及父目录。普通未暂存差异在实际执行时仍会读取受跟踪的工作区文件，不能将它描述为只读索引和对象，也不能据此保证所有受跟踪路径都已逐一核验。
3. 标准 Maven 3.9.x 的常规构建/测试绑定为独立执行计划，再交给审核 AI；批准后直接启动固定 Java/Maven 参数，不使用 shell 或工作区包装器。
4. 审核模型可独立配置厂商、模型、地址、协议格式和凭据；默认沿用主模型及其格式。改变厂商或地址时不自动转发主模型凭据。
5. 审核只接收限长的用户内容、工具调用投影和当前执行计划；不接收助手自由文本、工具返回内容或配置密钥。
6. 明确区分本地放行、AI 放行、复用、超时、格式错误、不支持与条件变化；按任务记账和缓存。
7. 增加原生查询、权限模式、模型配置、请求投影、失败回退和集成回归测试；仅使用本地夹具。

## 兼容约定

- 默认 `review`；显式 `mode` 优先于 YAML 的旧布尔字段。未设置时保留旧行为。
- `manual` 对 shell 请求逐次确认；`allow-all` 是用户显式选择的原始 shell 全放行，不能称作沙箱。
- 模型不能把未生成执行计划的任意命令自动放行；无法可靠解析、无法绑定程序或未通过安全检查的命令继续转人工。通过这些检查的剩余查询可进入无工具分类器。受支持 Maven 构建可以写文件与执行项目代码，不能归类为只读查询。
- 参考项目将语法解析、权限判断和无工具分类器分层。本实现的本地规则和 AI 路径现在共用同一份参数、连接操作符和 stderr 重定向解析结果；总长统一为 4,096 字符，不再保留普通命令的 128 字符分支。通过结构和安全检查的剩余查询交给分类器；计划绑定工作区、实际外部程序、Git 配置和可识别的路径操作数。批准后重新生成并比对计划，执行重新序列化的参数，不直接执行模型提供的原始 shell 文本。删除、安装/发布、解释器、网络上传、敏感路径及不支持的展开仍转人工。
- 本地只读链支持工作区内多目录 ls、Git status/diff/log、安全字面量 echo、head/tail/wc -l，以及工作区普通文件的 wc -c，最多 12 段，接受 `&&`、`;` 与单个 `|`。`2>/dev/null` 可按段丢弃 stderr，`2>&1` 可把 stderr 合并到后续管道；Windows 分别改为 `2>NUL` 或保留 `2>&1`。ls 保留选项和路径；`*/` 显式展开为最多 128 个非隐藏目录。ls/wc 操作数逐级检查工作区边界、链接、设备和敏感路径，并使用 `--` 分隔选项与操作数。程序、配置和路径通过复核后本地放行；剩余可审核查询进入 AI，而不是仅因未命中本地规则就直接询问用户。
- Git 配置指纹用于各 Git 执行计划。精确的 `git branch --show-current` 不读取工作树，允许配置中存在 clean/process 过滤器，但仍拒绝外部/条件配置等不确定情形；其他 Git 查询保留严格过滤器检查。
- 当前目录 `.` 和 find 的目录操作数可参与分类器执行计划，例如 `find . -maxdepth 1 -name README.md`；按路径语义校验目录，不能误用“必须是普通文件”的条件。find 的 -L/-H/-follow、执行/删除选项、敏感或越界路径仍在本地拦截。Windows 使用 Git 安装中的类 Unix find，不把系统同名文本筛选工具当作替代。
- 这是有界 Java 解析器，没有移植参考项目的完整 Bash AST。`||`、变量/命令展开及文件读写重定向仍不支持；组合 rg 文件清单借助 Git ls-files，和独立原生 rg 的忽略规则存在差异。路径检查不是操作系统沙箱，也不能消除检查后到执行前的全部文件系统竞态。
- 不修改参考项目，不执行真实收费模型请求，不自动提交或推送。

## 原生文件查询的统一执行

`where /r . AGENTS.md`、固定 `find` 写法及受支持的 rg 文件名/正文查询都转换为受限计划，共用 Java 原生执行器。在 `review` 模式，只要解析和工作区身份检查通过，就直接本地放行，不调用审核 AI，不启动 shell 或外部程序。

`NativeSearchQuery` 负责词法、rg 参数和末尾单个 head 的解析；引号内 `|` 保留为正则内容。支持 `rg --files`、正文 `-n/-i/-F/-e/-g` 及对应长选项、`--`，最多 32 个工作区内相对目录或文件；glob 支持 `*`、`?`、`**` 与否定模式，不支持 `[]/{}`。RE2J 用于线性时间的正文和 glob 匹配，不支持 PCRE 回溯引用或前后查找。命令最多 4096 字符、64 组 glob、16 个搜索模式，每个模式最多 2048 字符。

`rg --files` 后可以接一个受限 `sed 's#前缀##'` 前缀裁剪阶段，再接受 `head -N`。该变换在 Java 结果行上执行，不启动 sed；前缀必须是工作区相对路径且不含展开、通配符、父目录或替换内容，并且只能用于文件名列表。

唯一可接受的末尾阶段是 `| head -N`、`| head -n N` 或 `| head --lines=N`（N 为 1～1000），它仅转成结果预算，不启动 rg/head 进程。正文输出路径和可选行号，统一遍历保证结果顺序稳定、重复范围不重复返回；head 和输出等上限先达到者生效。变量/命令展开、重定向及任意其他管道仍需人工确认。

where 写法接受 `where.exe`、`/R`、用引号包裹当前目录 `.`，可组合已有受限文件名模式，例如 `where.exe /R "." AGENTS.md README.md "*.java"`。这不代表支持任意 where 参数：只查当前工作区，不接受父目录、外部目录、路径模式或未知文件名模式，不展开 PATH/PATHEXT。输出使用绝对路径；无匹配时按原生查询统一约定成功返回并提示“未找到匹配文件”。

三类语法共用工作区规范路径和稳定目录身份复核；遍历排除 `.git/.harness`、跳过符号链接与 junction，并保留访问数量、结果数量、输出、深度、时间及中断限制。语法适配不会扩大执行权限，也不会在检查失败后自动改成执行原始 shell。

正文读取额外限制为单文件 1,000,000 字节、每查询累计 8,000,000 字节；读取前后复核文件及祖先目录身份，跳过过大、含零字节或无效 UTF-8 的文件。`.env`、凭据目录、私钥等常见敏感路径不会因显式路径或 `--hidden` 被放开。查询继承 10,000 次访问、1,000 条结果、11,000 字符输出、32 层深度与 2 秒协作式预算；这不是操作系统强制超时，也不保证识别普通源码中的所有秘密。原生 rg 查询不读取 `.gitignore/.ignore`，不能等同完整 rg 的忽略文件语义。

## Maven 构建和测试的 AI 审核

`MavenBuildQuery` 单独解析 `mvn` 与 `mvn.cmd`，接受 `validate`、`compile`、`test-compile`、`test`、`package`、`verify`，支持 `-pl`、`-am`、`-o`、批处理选项和经过检查的普通 `-D` 属性。上限为 4096 字符、128 个参数，不再套用普通命令的 128 字符限制。`clean/install/deploy`、直接插件目标、外部 settings、变量展开、代码加载参数和 shell 串接不会生成自动构建计划。

`MavenBuildExecution` 从工作区以外的标准安装发现 Maven 和 Java，要求 Maven 3.9.x，避免按 Maven 3.9 的配置语义错误解释 3.8 或 4。计划绑定规范工作区、选中模块、POM、`.mvn` 配置和运行时文件；`.mvn/maven.config` 每行一个参数，`.mvn/jvm.config` 仅接收受限的内存/处理器设置。`.mvn/extensions.xml` 与 POM build extensions、插件执行目标都会进入审核摘要。计划不读取或上传工作区外父 POM 和用户 settings/toolchains 的正文。

审核请求的 `actionType` 为 `maven-build`，包含原始命令、固定执行参数、构建目标/模块/插件/扩展摘要，以及保留当前用户任务的有界对话投影。分类器没有执行能力；它返回结构化允许后，`WorkspaceTools` 再校验计划并直接启动外部 Java + Maven Classworlds，不执行原始 shell 或工作区内包装器。JVM 与 Maven 环境注入入口被清理，子 Maven 沿用启动 ylc 的用户目录。用户 Maven 配置和项目插件仍按 Maven 行为生效，不能因此认为执行已隔离。

配置及运行时身份、内容进入批准缓存指纹，投影基于同一份已读配置字节。即使配置长度与修改时间相同，内容改变也会使旧批准失效；每次真正启动前再次检查，取消时停止复核。只在同一任务中复用仍有效的批准。AI 失败、超时、人工结论或本地条件不满足都不执行，交互终端转人工确认，无终端时拒绝。

Maven 会执行插件和测试代码，可写入工作区、其他当前用户可访问的位置及缓存，并可能联网。`-o` 仅限制 Maven 的依赖下载，不限制插件或测试自行联网。这个自动执行计划不是只读计划或操作系统沙箱；任意脚本及未支持目标仍需人工确认。

## 审核模型格式

主连接可通过 `api-format: responses` 或 `--api-format responses` 选择 Responses。审核连接默认继承主格式，`permissions.reviewer.api-format` 可独立设为 `chat` 或 `responses`；仅改同一连接的格式时保留密钥和请求头，改 provider 或地址则仍隔离主连接凭据。格式覆盖仅适用于 `openai`、`openai-compatible`、`openai-responses`，地址填写 API 根路径，不包含 `/responses`。审核分类为一次完整响应；主模型的 Responses 流式与恢复行为见[原生流式输出](NATIVE_STREAMING.md)。

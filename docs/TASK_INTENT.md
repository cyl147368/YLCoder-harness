# 任务意图识别

意图识别用于区分“回答、检查、给方案、改代码、执行任务”，与命令风险审核是两层机制。默认自动识别，不增加分类模型请求。

| 模式 | 示例 | 行为 |
|---|---|---|
| chat | 你好 | 不发送工具结构，直接回答 |
| analyze | 看下当前项目的优缺点、怎么修复 | 仅提供文件读取、搜索、目录、变更概览及已启用的联网工具 |
| plan | 先给我修复方案 | 只读调研，输出方案，等待实施要求 |
| edit | 可以，开始实现；修复这个问题 | 恢复常规工具，保留原有命令权限审核 |
| execute | 运行测试、编译项目 | 恢复常规工具，保留原有命令权限审核 |
| auto（未确定） | 本地规则无法可靠匹配的任务 | 保留常规工具，由主模型结合原始请求判断；不视作明确修改授权 |

## 使用

直接输入任务即可。每项任务前显示识别结果和来源。

- `/intent`：查看设置与当前活动历史的判断，不调用模型。
- `/intent plan`：随后任务固定使用方案模式。
- `/intent edit`：随后任务使用实施模式。
- `/intent auto`：恢复逐任务自动识别。
- 非交互可用 `ylc --intent analyze run "看下当前项目"`。

手动设置只对当前进程有效，持续到再次切换；恢复其他会话也保留显式设置。自动模式每项任务重新判断，恢复和回退后使用当前活动历史，不读取已回退掉的消息。单独输入“继续”最多检查最近 8 项用户输入，跳过助手和工具内容；找不到明确前项时交给主模型。

## 实现与边界

TaskIntent 使用有界本地规则，单条最多处理 8192 字符，忽略反引号代码块、行内代码和引用行。明确“不改文件”、方案及疑问形式优先于修改关键词；输入过长或无法匹配时保留主模型判断。它不是额外的语义分类模型，也不能保证所有自然语言都识别正确。

CLI 按本轮意图附加固定系统指引；不复制用户原文到系统权限位置。ToolRegistry.filter 同时过滤请求里的工具定义与 CodeAgent 的执行查找，模型即使主动调用被隐藏工具，也只能收到“工具不可用”。只读模式暂时禁用所有 run_command 和未知 MCP 扩展，包括只读 Git shell 查询；可用 changes 查看变更。需要运行测试或命令时明确提出执行任务，或切换 execute。意图切换不会绕过原有命令审核。

chat 省去全部工具结构；analyze/plan 省去写入、命令和扩展工具结构。固定意图提示本身会增加少量输入，实际 token 与费用依赖厂商分词、缓存和后续轮数，不能把结构字节减少直接当作计费 token 节省。

参考项目的输入路由与显式模式分离提供了设计思路；没有把其权限分类器当作任务意图识别，也没有声称移植通用意图分类器。本地分流规则和 Java 工具过滤是本项目实现。

## 验证

单元测试覆盖否定、疑问、引用、继续、手动覆盖、只读工具边界；本地 HTTP 测试覆盖交互切换、恢复方案、零额外分类请求，以及 allow-commands 下隐藏写入仍不能执行。scripts/smoke_intent.py 可对源码包或全局启动器运行实际进程验证，报告各轮工具结构和 UTF-8 字节数，不使用真实厂商。

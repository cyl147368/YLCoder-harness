# Gemini 有序部分连续性

Gemini 适配器现将完整、受支持的 `candidate.content.parts` 数组存入不可变助手消息元数据 `gemini.contentParts`。可见文本由非 thought 文本部分拼接。thought 文本不出现在可见回答中。带签名的 thought/文本部分和函数调用保留精确 JSON 值与顺序，包括交错文本、可选协议 ID 和调用签名。JSON 空白被规范化，对象/数组结构和字符串值保留。

后续请求中，适配器先验证已存数组再回放。可见文本、调用数量/顺序、函数名、结构化参数、可选协议 ID 和各调用签名必须与中立消息/调用一致。不一致或不支持的回放在 HTTP 请求前失败。厂商局部严格解析器拒绝已存 parts 和函数参数中的重复对象键、尾随 JSON 值。此校验检查一致性，不是厂商签名的密码学验证器。文本/thought 签名是不透明值，无法在本地认证。

此文本编码工作流仅接受文本和函数调用 parts。未知字段、多模态部分、非法文本/签名/参数、重复协议 ID，以及只有 thought 的成功完成都会安全拒绝。不声称支持多模态。长度受限、安全限制或拒绝的候选不提供可执行调用或可回放元数据。

没有消息元数据的旧会话仍使用调用级 `gemini.functionCallId` 和 `gemini.thoughtSignature` 回退。协议中绝不虚构缺失的 ID 和签名。没有厂商 ID 的调用所使用的内部 ID 仅用于本地关联。

## 新增验收

`GeminiMetadataTest` 现覆盖：

- 双回合的精确交错 thought/文本签名与并行函数调用，以及正确结果 ID。
- 最终 thought/文本回答序列化，随后用户请求回放。
- 篡改可见文本、调用名、参数、ID、签名、缺失调用、格式错误回放及错误元数据角色，在 HTTP 前拒绝。
- 解码和回放中的不支持/格式错误文本、多模态、函数、签名和 thought parts；重复/尾随 JSON 与格式错误旧元数据在 HTTP 前失败。
- 长度/安全/拒绝结果既不暴露可执行调用，也不暴露回放证据。
- 已有可选 ID/签名行为与调用级旧回退。

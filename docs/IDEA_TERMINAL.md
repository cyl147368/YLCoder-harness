# IDEA 内置终端卡顿排查

## 默认保留固定底栏

```powershell
ylc
```

默认保持之前的状态位置，JetBrains/IntelliJ 环境标记不会自动改布局。减少重复重绘的优化保留。仅在需要手动选择随正文滚动的兼容状态区时使用：

```powershell
ylc --inline-status
```

状态仍显示在输入之前，随正文自然滚动。模型、厂商、输入/输出 token 和缓存信息保留，颜色、Tab、Esc、Ctrl+C 不因此关闭。终端颜色也有问题时可使用 `ylc --inline-status --no-color`。此参数需要更新后的运行包，已启动的旧进程需退出并重新启动。

## 从代码中确认的问题

此前每个文本增量都会调用 `TerminalUi.answer()` 和 `phase("正在输出")`。`answer()` 在判断是否已经展示标题之前就清理底栏；`phase()` 随后又绘制分隔线和四行数据。Markdown 的文本此时还在缓冲中，没有实际正文输出，却持续擦除并重画五行，伴随多次 flush 和原生屏幕查询。小片段多时终端工作量随片段数增长。

目前标题只在首次显示时清理底栏；完整回复真正输出前显式清理。相同阶段最多每 250 毫秒刷新一次，阶段变化、工具事件和用量更新立即刷新。底栏内容、颜色、屏幕尺寸和位置均不变时跳过 ANSI 绘制；正文输出清理、窗口调整和滚动仍会触发必要重绘。没有增加后台动画线程，也没有增加模型请求。

Windows 固定底栏使用 Win32 缓冲区坐标。IDE 的伪终端即使暴露了控制台句柄，坐标也未必与 IDE 显示视窗一致。默认仍尝试原有固定底栏，只有显式 --inline-status、输出重定向、无颜色模式或原生能力不可用等原有条件会选择文本布局；不根据 IDE 名称自动移动状态位置。没有在真实 IDEA 终端测量性能，不能据此断言所有 IDEA 版本都有同一种缺陷。

## 区分不同的“卡”

| 现象 | 更可能需要检查的部分 | 对比方法 |
| --- | --- | --- |
| 打字、粘贴、滚轮和大量输出延迟，外部终端正常 | IDEA 终端渲染、行编辑或终端引擎兼容 | 在相同工作区和配置下对比 `ylc --inline-status` 与外部 Windows Terminal |
| 输入正常，思考很久后整条 Markdown 一次显示 | 当前交互 Markdown 等待完整回答、模型或工具等待 | 查看 `/logs` 中各次请求/响应和工具过程；当前不会逐字渲染交互 Markdown |
| IDEA 和外部终端都等待很久或报 HTTP 错误 | 厂商网络、响应时延、工具执行或上下文规模 | 按日志定位，不依靠更改终端颜色解决模型等待 |

如果切换到普通布局后仍只有 IDEA 卡，可在 IDEA 的 Tools → Terminal 设置里对比该版本提供的不同终端引擎。设置名称和选项随 IDEA 版本变化；未对真实 IDEA 操作做性能测量。不要仅为性能把 `TERM` 改成 `dumb`，这会关闭增强输入和 Tab。

## 验证边界

`TerminalPerformanceTest` 以可注入屏幕和单调时钟模拟一秒内 1000 次增量：要求同阶段只有四帧绘制、八次屏幕查询、没有反复清行，状态和用量变化立即展示。另覆盖相同内容跳过、清理后恢复、颜色和尺寸变化重绘、默认布局和显式启动参数。模拟输出量不等于真实 IDEA 帧率或模型延迟；实际体验需在用户的 IDEA 版本中确认。

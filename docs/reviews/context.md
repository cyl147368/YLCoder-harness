# 上下文压缩评审

## 变更

ContextCompactor 现在保留原始任务、最近用户指令、所有已有系统消息、最近助手消息和最近完整工具交互。较旧助手工具调用及其结果作为不可拆分块移除。保留的工具调用 JSON 绝不缩短。孤立、缺失或重复工具结果的无效历史以有界错误在本地失败。

历史摘要使用一条助手消息，只含有界数字计数。它绝不包含工具输出、工具名称、路径、参数或历史自由文本指令，绝不创建 SYSTEM 消息。重复压缩把摘要规范化为一条消息；输入和限制未变时保持幂等。

缩短可选文本后，不可缺少的上下文若仍超过配置估算，压缩抛出有界错误，不回显源码文本。智能体因此可在发送过大模型请求前失败。估算包含调用 ID 和工具结果元数据，但仍是近似值，不是厂商分词器。

## 验证

核心 Maven 测试套件：27 项测试、0 失败、0 错误。针对性的 ContextCompactorTest 有 9 项，覆盖系统/任务/最近意图保留、配对和多工具交互、严格过大上下文失败、错误历史、重复调用和新轮次间幂等，以及有界摘要计数。已有恢复和边界测试也通过。

等价命令：mvn -pl harness-core test -DforkCount=0。测试通过 Java 21 Maven 启动器执行，因为当时此宿主上的 exec_command 因 Windows CET 启动错误失败。证据：harness-core/target/core-audit-test.log。

| 测量项 | 本地估算 |
|---|---:|
| 压缩前 | 240,831 |
| 压缩后 | 448 |
| 配置预算 | 500 |

断言验证两条系统消息和原始任务不变、最近工具交互仍配对、每个保留调用/结果配对、重复压缩不变，并且结果符合配置估算。此合成重复输出夹具只证明上下文减少受限；不测量真实 API token 节省、编程成功率、延迟或分词准确度。

## 取舍与剩余范围

数字摘要有意省略历史细节；智能体可能需要重新读取源码文件。原始任务和最近指令保留，中间用户轮次可能移除。过大的不可缺少工具参数会明确失败，避免损坏 JSON。厂商原生 token 统计和输出预留是独立问题。此次限定范围的后续工作没有修改其他生产类。

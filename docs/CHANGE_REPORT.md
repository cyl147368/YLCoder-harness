# 工作区修改报告

write_file 和 edit_file 工具在成功改变内容后返回包含上下文的统一差异。报告包含工作区相对路径、删除/新增行，以及每个差异块周围最多三行未变内容。创建文件以 /dev/null 为原路径；新建空文件也会有明确的创建报告。路径加引号，路径中的换行会转义。字面量编辑仍保留 SHA-256 结果和可选的过期内容保护。

changes 工具接受空 JSON 对象，返回当前工作区工具注册表中每个路径首次成功修改以来的累计**净变更**。重复写入保留原始基线。恢复为原始字节后，该路径从报告中消失；后续编辑仍与同一基线比较。相同写入和没有实际变化的字面量编辑报告“未改变”，不建立新基线。参数/哈希/原子写入检查失败也不建立基线。

changes 工具读取当前文件，因此会反映后续外部修改或已追踪路径的删除。它不扫描无关路径，不发现所有 shell 命令编辑，也不要求 Git。新建文件随后被删除时无净变更。生成报告时再次检查文件包含关系；若路径被替换为逃逸符号链接/junction，会被拒绝。

## 上限与生命周期

- 基线仅在一个注册表生命周期内驻留内存，不保存在检查点中，也不会带入恢复的 CLI 调用。
- 最多保留 128 个路径和 8,000,000 字节原始内容。撤销后仍保留基线，确保后续变更仍正确比较原始内容。修改若会超过任一上限，会在替换文件前失败。达到容量上限时仍可执行无实际变化的修改。
- 原始文件和替换文件都必须满足现有 1,000,000 字节文件上限。尤其 write_file 为追踪完整原始字节，不能覆盖过大的原文件。
- 修改差异限制为 4,000 个字符，另加截断标记和简短状态。累计报告使用现有 11,000 字符工具输出上限。截断会明确标注；这些输出用于审阅，不保证是完整补丁。
- 覆盖无效 UTF-8 或含 NUL 的原文件时返回二进制变更摘要。文本替换/编辑验证、原子替换和 POSIX 权限保留仍然生效。
- 已追踪修改后，当前文件若增长超过 1 MB，会报告为已修改，但无法提供文本差异。

差异算法使用有序的唯一行锚点和最长递增子序列，再裁剪替换间隙，避免二次方 LCS 表。超过 50,000 行时，输出一个裁剪共同前缀/后缀后的替换块；重复行区域也可能产生非最小差异。此降级方式用行偏移索引，避免为每一行分配行对象。设计优先保证可预测的有界处理，而非最小补丁。

## 本地验收证据

独立 Java 21 验收运行器通过 25 项测试，并记录四项 Windows 平台跳过。它将当前工作区工具和测试编译到 harness-cli/target/workspace-change-acceptance，不运行 Maven，也不改变共享已编译类。此历史独立验收之后，负责人仍需运行组合 Maven reactor。

新增检查覆盖创建/空文件、无变化操作、重复修改/撤销、过期编辑失败、多段上下文差异、外部删除、Windows junction 逃逸、快照/输出上限、接近 1 MB 的单行和 200,000 行文件。确定性的 300 例编辑生成器从展示的完整差异块重建预期结果行。其他检查覆盖末尾换行标记、二进制摘要，以及转义/截断的标题。现有工作区工具检查验证字面量编辑、命令超时/审批和支持的包含关系/权限行为。

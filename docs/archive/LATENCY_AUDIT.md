# 独立首个可见文本审计

只读审阅 `scripts/measure_latency.py`、`scripts/check_latency_measurement.py` 和 `StreamingOutput`。未访问凭据/控制器、外部请求、改源码或运行Maven。没有重复localhost运行：所审阅修改未发现需要再次模型/传输测试的疑点。负责人正在重跑已有打包localhost对照。

## 验收评估

测量在读取线程 `read(1)` 后立即为第一个非空白stdout字节记时，与进程启动/完成使用相同单调时钟。不从最终CLI JSON或进程完成推导首文本。`StreamingOutput.delta` 刷出实际厂商碎片。暂缓结束localhost对照等待该字节，确认测量future仍未完成后才允许结束；这是适当的独立早期输出契约。

通过样本要求退出码零、首可见时间先于观察的完成时间、精确stdout短语（允许前后空白/换行）、唯一持久化精确助手回答、无工具调用/结果、COMPLETED检查点、厂商/模型/工作区匹配、配置不变、无意外非状态文件。未完成SSE、格式错误JSON、工具响应是负对照。一次迭代上限使完整工具响应到达也不执行修改；zeroTools仍拒绝样本。失败记录与成功一起追加，报告须全部通过。请求流式明确限定：通用网关stream:true仍可能返回JSON，这些测量本身不能认证SSE。

用量合理限定为CLI归一化合计token。输入/输出/缓存分项null；缺失可能呈零，可用性字符串明确说明。没有虚构分项或账单结论。递归脱敏在JSON编码前替换字典键和值中的所选凭据；转义人工密钥对照验证此性质。报告不含原始stdout、stderr、模型响应或请求头。

## 限制与小型加固机会

- **完成时间是观察到wait返回，不是厂商生成结束。** 首文本包括Java启动、配置/会话/工具准备、网络/模型、输出刷新、Python调度。进程完成包括最终检查点/报告/JVM关闭。应标为打包CLI用户可见延迟。同步样本自然在进程退出前不久发首回答，不能建立早期模型流式。重复/顺序平衡减轻固定顺序偏差，但不是稳定生产提速结论。
- **读取线程调度可能拒绝原本有效的短回答。** 完成时间在join读取器前捕获。进程在Python调度stdout读取器前退出时，首字节时间可能晚于完成，validTimingOrder会正确拒绝虚构早时间。保留失败样本，将其理解为测量顺序不确定，不能归因厂商延迟。暂缓结束对照为早期输出正确性避免此歧义。
- **罕见启动/清理OS错误可能中止报告而未保留失败。** Popen启动错误已捕获，但timeout/finally的child.kill及保护区域外一些file/stat可能抛OSError，此时main追加结果前停止，不同于普通超时/解析/验收失败。适度修复为捕获清理OSError、标固定cleanup_failure、继续保留样本，不记录异常文本。这是源码错误路径缺口，普通localhost未复现。
- **清理是有界尽力操作。** 超时只杀Java子进程，最多等待五秒，然后每个读取器最多join两秒。读取器超时样本失败，活线程/管道可能留到EOF；不保证全进程树清理。禁用工具和一次迭代的普通探测不会启动命令/MCP子进程。应记录此边界，不称样本超时为精确墙钟上限或保证清理。

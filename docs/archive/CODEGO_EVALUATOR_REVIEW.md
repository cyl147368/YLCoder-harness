# 显式启用评估器正确性审阅

独立检查器过去在模型可修改工作区中用默认classpath/sourcepath编译，再从同目录运行，允许相邻旧类、隐式源码和默认注解处理器发现，也将隐藏Check.java暴露给后续代码。现在仅复制Subject.java到全新隔离临时目录，写自己的Check.java，以Java21、`-proc:none`、显式空classpath/sourcepath目录、新`-d`输出目录编译，再仅执行这些类。编译失败绝不运行断言；超时报告当前阶段，不输出原始诊断。源码缺失/不可读或编译器不可用返回安全失败。这隔离编译输入，不是执行Java的OS沙箱。

评估器现接受现有任务ID中的 `--task`；所选任务仍运行基线和紧凑两变体、已有重复/迭代限制和缺陷/修复对照。已有离线策略及token统计保留。修复源码被删除/不可读时记录null源码哈希，不中止报告；子进程JSON非对象记NO_RESULT。

当前HarnessCli没有CLI max-output-tokens参数，因此未增加评估器参数或YAML重写。用 `--config` 显式可信真实YAML中的 `agent.max-output-tokens` 设置正值；加载器已验证正数，厂商收到此值。负责人掌管配置和全部真实请求。审阅未查看、复制或记录凭据/私密配置。

真实限制仍明确：用量来自适配器，零可能表示缺失；真实运行未捕获序列化厂商请求token数或首段文本延迟。这是配对上下文的预置回放负载，不是广泛编码能力基准。选择任务只建立该任务证据。

未运行Maven、网络或模型调用。修改限于scripts/evaluate_coding.py和本审阅。语法验证通过；负责人应在显式真实评估前重跑独立本地检查器对照。

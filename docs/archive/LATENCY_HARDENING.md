# 延迟测量失败保留

独立延迟审计发现，罕见的操作系统启动、检查、清理错误可能使报告生成中止。负责人在首次真实测量后解决了此问题。遇到意外测量 I/O 错误时，`measure_sample` 会保留脱敏的失败记录及已知的计时字段。超时后的 kill、poll、wait 和管道关闭错误会被捕获、记为清理失败，并使样本无法通过验收。不发布异常详情或捕获的输出。

负责人在修复后运行了一次 `python scripts/check_latency_measurement.py`。五项真实 JAR 的 localhost 响应预期全部符合：在暂缓结束信号前观察到早期文本；同步回答被接受；未完成的 SSE 被拒绝；格式错误 JSON 被拒绝；工具修改尝试被拒绝且没有执行。递归处理转义后的人工密钥脱敏检查通过。另外两项合成操作系统路径对照通过：超时 kill 错误保留带清理失败标记的失败记录；检查 I/O 错误保留已知计时且不含私密异常文本。证据位于 `target/latency-controls-hardened.json`。

这次错误路径加固没有改变 Java 产物，也没有追溯修改最初六个真实样本。其报告保留原始测量脚本哈希。清理仍是有时间上限的尽力操作：仅停止 Java 子进程，读取线程的等待有限，不保证整个进程树均被终止。本次修复没有新增真实测量或运行 Maven。

# 多文件评估器审计

负责人处理：下方四项要求均在最终验收前解决。即时历史输出与完整带行号夹具比较，要求发现和计数器。每个任务现含无关BuildIdentity源码，执行后比较初始字节。匹配成功对报告两tokenizer/字节合计与降低比例；不把节省阈值混为正确性。javac验证用全新显式classpath/sourcepath、-proc:none、新cwd。最终证据 `benchmarks/multifile-evaluation-v1.json`；以下原发现记录审阅缺陷。

只读源码审计 `scripts/evaluate_multifile.py` 和当时的 `scripts/multifile_fixtures.py`。未改源码、运行Maven、模型调用或检查器对照。夹具仍由负责成员改进；以下发现对应当时版本。

## 所需修复

1. **P2：历史负载可失败而评估通过。** Policy.do_POST检查前步骤结果ID/顺序，但不检查history-*或discover的内容/成功。每次日志读取都返回Tool failed:...仍满足，后续源码读取/已知修复可通过。测量请求token负载会明显变小，却未证明预期历史压缩。验证每个新历史结果的确定夹具内容或有限已知哨兵，验证发现包含必需源码路径。旧可选历史之后可丢弃，但应在紧接请求校验。运行结果增加显式历史负载和发现布尔。

2. **P2：unrelatedSourcesUnchanged当时无实质内容。** 三个任务每个源码都被编辑，筛选edited之外名称的生成表达式为零元素，总true。每任务增加无关Java源码，接受前断言独立记录数量大于零，执行后验证精确字节/哈希。夹具成员可能正在修复；存在前不能把true作为证据。

3. **P2：摘要不能支持配对token效率结论。** 每行有token/字节，但汇总只有通过数、运行数、进程中位时间。紧凑输入相等或更多仍overall passed:true。增加成功的匹配(task, repeat)对、每对token差值/降低比例、各tokenizer汇总。失败/未完成对单独报告，不把短历史默认为节省。若正节省是验收要求需明确，否则只报告测量而不作节省结论。交替变体顺序有用，repeat=1仍只是样本而非稳定速度估计。

4. **P3：新运行时隔离良好，编译解析继承环境。** 新目录编译、运行classpath仅该目录，旧compiled/*.class不能满足运行断言。但javac无显式-classpath/-sourcepath/-proc:none，子进程继承环境/cwd。外部CLASSPATH或注解处理器可影响编译。无依赖夹具应显式空/新classpath、禁注解处理、新目录cwd。此前结论应仅限不依赖旧输出；不证明敌对代码沙箱。

## 限定范围内合理的检查

- 前回合工具结果按精确预期调用ID选择，顺序与请求比，重复也不能满足相等。
- 过期哈希拒绝要求预期诊断，授权修复前验证全部原始源码。
- 最终可信检查在harness进程退出后创建，源码编译到独立新输出，运行classpath不含代理类输出。
- 明确范围为脚本化已知编辑、过期编辑恢复，不声称模型推理/账单/生产延迟。恢复应限定为过期编辑恢复，不测试进程崩溃检查点/resume。
- 小源码投影按行检查，但脚本策略已知修复。通过证明相关上下文传递和保留，不证明跨文件推理推导修复。

# 实际 CLI 首个可见文本测量

仅实现了 `scripts/measure_latency.py`、`scripts/check_latency_measurement.py` 和本审阅文档。运行器在 Popen 前立即记录单调时钟，观察实际 Java CLI 标准输出读到的第一个非空白字节，并独立记录进程退出时间。标准输出与标准错误各有独立、有限的读取器（各存储一 MiB）；子进程只调用一次，进程和读取清理有时间上限，不进行重试。缺失首字节的值保留为 null，并无法通过验收；未完成的流虽然可能产生早期文本，仍不能通过完成性验收。

每个样本使用新的、显式信任的配置，限定一次迭代、64 个输出 token，命令和 MCP 权限为 false。只请求 LATENCY_PROBE_OK；仅接受已完成会话、唯一且精确的助手回答、无工具调用或结果、精确标准输出、匹配的工作区/厂商/模型，以及没有意外工作区路径的样本。模型返回工具时，在执行工具前到达 MAX_ITERATIONS，并验收失败。不打印原始标准输出、标准错误、模型错误或请求载荷；错误类别使用固定字符串。

外部 CLI 运行必须显式提供 `--live`、不含用户信息/查询/片段的 HTTPS 端点、模型和非空凭据环境变量。重复次数默认三次，范围为一至五次。每次重复交替流式和同步顺序；超时上限为 90 秒；失败样本一直保留为失败。凭据保留在环境变量引用中，不写成配置值。报告字符串和键在 JSON 编码前进行递归脱敏。

计时从 CLI 启动到观察到标准输出或进程退出，包括 JVM 启动和读取线程调度。请求流式模式不能证明网关实际返回 SSE：支持 JSON 回退，并正确标记为请求的模式。流式 CLI 的终端摘要只打印适配器归一化的合计 token 数。运行器报告这个合计值，输入、输出和缓存分项为 null；不会虚构分项，也不会把零值当作用量可用的证明。每份报告都明确说明此限制；它不验证厂商账单。

```text
python scripts/check_latency_measurement.py --java D:\software\jdk-21.0.10\bin\java.exe
```

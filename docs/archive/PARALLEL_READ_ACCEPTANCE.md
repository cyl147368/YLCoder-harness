# 有界并行读取验收

已实现 `harness-core/src/test/java/dev/codeharness/core/agent/ParallelReadsTest.java`。没有修改生产文件。

八项测试验证：

- 六次显式安全读取重叠，观察到的活跃并发不超过配置上限二。
- 两个读取按相反调用顺序完成，但转录和每个持久结果检查点仍在协调器线程按调用顺序记录。
- 助手检查点先于全部读取启动；修改屏障等待前序读取，后序读取观察到修改。
- 默认参数及六参数构造器保留并发一；即使请求并发四，未分类工具仍顺序执行。
- 结果检查点失败会中断运行中读取，阻止后续修改和模型执行。
- 阻塞读取批次期间取消会中断两个协作读取，阻止后续工具及模型执行。
- 最大迭代终止不执行工具；助手检查点失败不启动读取。
- 故意不协作扩展仍被暂缓时取消能够返回；测试随后释放并 join 扩展，证明协调器清理有界，不声称强制杀死工具。

协调使用有界超时 latch。顺序负对照在第一调用被故意暂缓时使用100 ms有界 latch 等待；没有产品延迟或速度断言。全部创建的工具线程由测试清理释放或中断。

## 验证

使用 JDK21 运行 `python harness-core\target\parallel-read-acceptance\verify.py`。它依据现有 Surefire依赖 classpath，把当前核心生产源码和新测试编译到私有 target 目录，再调用全部八个 JUnit 测试方法。结果：**8项通过**。生成辅助脚本不是交付物。

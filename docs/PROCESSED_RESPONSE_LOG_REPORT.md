# 可读回复日志测试报告

验证日期：2026-11-06。

## 这次改好了什么

现在打开执行日志，就能直接看模型的回复正文、工具调用和 token 用量。返回的 JSON 外壳和一条条 SSE 事件不再写入新日志，也不生成隐藏的原文副本。

- 正常回复：直接显示正文，流式文字会合并。
- 调用工具：显示工具名称和参数；没有文字正文时明确说明，不留一个让人误以为漏记的空块。
- 审核回复：显示“允许 / 需要人工确认”和简短原因。
- 请求出错：显示 HTTP 状态码、错误原因，以及厂商提供的错误类型、错误代码和请求 ID。
- 流式中断：保留已经收到的文字预览，并明确标为“未完成”，不会冒充完整回复。

请求仍保留实际发送的正文，重复提示词通过引用定位。日志处理不改变请求、不减少模型实际输入 token，也不为整理回复额外调用模型。

这些是本轮日志改动的针对性验收，没有重新执行全项目完整测试，也没有调用真实模型厂商。

## 现在怎么用

退出正在运行的旧 `ylc`，再启动并提交一次任务，输入 `/logs`，用编辑器打开列出的最新 Markdown 文件。重点看同编号的“HTTP 请求报文”和“模型回复”。

旧文件保持原样。新格式不会追溯改写已经生成的原始响应日志。

完整回复的展示上限是 1,048,576 个 Java UTF-16 单元；未完成片段、工具结果和错误摘要受 `tool-result-max-chars` 控制，默认 2,000。超限会标注截断。单个任务日志最多 32 MiB。当前不展示厂商不透明响应扩展字段，日志也不能用于重建新任务的原始响应字节。

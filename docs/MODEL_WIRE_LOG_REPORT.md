# 模型报文日志测试报告

验证日期：2026-11-06。

## 这次解决了什么

以前的日志能看到提示词和工具摘要，但记录的是程序内部消息，无法完整回答“到底向厂商发了什么、厂商原样回了什么”。这次把记录点移到了 HTTP 传输层。

现在，每次调用都有对应的请求正文和响应正文。重复的提示词、工具定义和长文本只保存一份，其他位置保留可还原的引用。工具过程仍用简短预览，真正发给模型的工具结果另外保留在请求报文里。日志不会改变模型输入，也不会额外调用模型。

## 验证结果

**全量 Java 验收通过：942 项中，926 项通过、16 项因平台条件跳过，0 失败、0 错误。打包 JAR 和已安装的全局 ylc，分别通过全部 9 个端到端场景。**

端到端测试启动真实 CLI 进程，连接本机模拟模型。测试把日志中的引用展开，再与服务端实际收到的请求、发出的响应逐项比较。JSON 比较的是字段和值，SSE 比较收到的文本；已配置的模拟凭据在期望值中先做相同脱敏。

两套端到端验收共发起 **40 次 localhost 请求**，包含任务、审核和重试，不含 Java 单元测试内部请求。没有调用真实厂商。

新增的传输层测试覆盖 6 类适配器：OpenAI 兼容 Chat、Responses、Anthropic、Gemini、Azure、LangChain4j OpenAI；并验证 Chat/Responses/SDK 的原始 SSE、HTTP 错误、调用结束后迟到回调的记录隔离、8 MiB 上限以及记录器失败不改变模型结果。

去重测试检查了长工具结果、未知协议字段、JSON 路径中的特殊字符、正文恰好包含引用占位字样，以及“超长正文脱敏后变短”的边界。脱敏发生在去重之前，已配置的模拟密钥不会落盘。

16 项跳过来自当前 Windows 环境的符号链接/POSIX 等能力条件，不计为通过。其他平台与真实厂商接口没有在本轮验证。

## 使用方式与边界

在交互中输入 /logs，打开对应 Markdown 文件，重点看同编号的“HTTP 请求报文”和“HTTP 响应报文”。想看展开后的单次完整报文，用仓库里的 scripts/read_model_trace.py；具体命令见 [执行日志使用说明](EXECUTION_LOGS.md)。

这项功能减少的是日志中的重复内容，不减少实际发送给模型的 token。已配置凭据会遮盖，JSON 会重新缩进，因此不承诺网络字节级还原。HTTP 响应最多捕获 8 MiB、单任务文件最多 32 MiB，超限或中断会明确标注。发送前已裁剪的工具内容、客户端未读取到的响应，以及旧版本从未记录的报文，都无法补回。

第三方 SPI 模型若没有接入观察器，仍采用明确标注的逻辑备用记录。本轮验证了协议样本、实际本机传输和 CLI 行为，没有证明所有厂商扩展都能兼容，也没有测量日志对延迟的额外开销。

## 如何复测

~~~shell
mvn -B verify
python scripts/smoke_execution_trace.py
~~~

Windows 全局入口可用：

~~~powershell
python scripts/smoke_execution_trace.py --launcher "$env:LOCALAPPDATA\YLCoder-harness\bin\ylc.cmd" --output target/model-wire-global-smoke.json
~~~

本机使用 Maven 离线缓存与 target/maven-review-settings.xml 完成全量验收。证据里的进程总时长包含 JVM 启动、重试等待和本机文件操作，不能拿来比较真实模型速度。

# 日志“看起来是空的”修复报告

验证日期：2026-11-06。

> 本文是当时版本的验证记录。后续已将新日志的响应改为整理后的正文和工具调用，不再保存原始响应 JSON/SSE；当前行为见 [可读回复日志测试报告](PROCESSED_RESPONSE_LOG_REPORT.md)。

## 问题是什么

旧日志为了去重，连第一次出现的提示词也替换成了 `[引用 wire-1]`，原文放在下面的 `new_content`。顶部的空 HTML 锚点只是跳转位置。内容没有因引用而消失，但这种排版很容易让人以为根本没记录。

## 现在怎么看

- 第一次出现：在 `body` 的原字段直接看到提示词、工具定义或模型回复。
- 再次出现：才显示引用，并在报文下标明首次内容在哪次请求、哪次 HTTP 尝试和哪个字段。
- 不再为 HTTP 报文输出空 HTML 锚点。
- `references` 或 `content_locations` 为空，只表示没有重复项或新增项；真正正文看 `body`。
- 旧日志保持原样，`scripts/read_model_trace.py` 仍能将旧版 `new_content` 引用还原为完整报文。

去重只改变本地日志展示，发给模型的请求不变。原有脱敏、截断标记和错误记录仍然保留。

| 特殊内容 | 正文恰好包含“引用”字样不会被误替换；特殊 JSON 路径可还原；定位文字不能插入伪造标题或 HTML |

**全局 ylc 的 9 个端到端场景全部通过**，共发起 20 次本机模拟模型请求。Chat、Responses、独立审核、三次重试、部分流中断、关闭日志、日志目录不可用和本地日志查询均通过。会话恢复后的新日志也能独立还原。

测试将日志还原后，与模拟服务端实际收到的请求和发出的响应逐项比较，JSON 字段和值、SSE 文本均一致（按既有规则脱敏）。没有调用真实厂商。

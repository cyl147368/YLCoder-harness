# 执行日志使用说明

YLCoder 默认把每次任务的模型请求、回复和工具过程写入本地 Markdown。日志独立于会话检查点，可用于查看实际提示词、分析重复输入、排查重试和工具失败。旧配置无需新增字段；退出旧进程后重新运行 `ylc`，从下一次提交任务开始记录。

## 先这样使用

在要处理的项目目录启动，提交一次任务，结束后输入 `/logs`：

```powershell
cd "D:\code\你的项目"
ylc
```

```text
/logs
```

界面列出**当前会话最近 10 个任务日志的绝对路径**，第 1 项最近更新。用编辑器打开某个 Markdown 文件，首次出现的报文正文直接展示，重复内容旁会标明原文的请求编号和字段位置。更多文件可以直接在列出的目录中查看。

不进入交互界面也可以查看：

```powershell
ylc logs
ylc logs 你的完整会话ID
ylc --workspace "D:\code\另一个项目" logs
ylc --json logs
```

- `ylc logs`：列出当前工作区各会话最近 10 个日志文件。
- `ylc logs 会话ID`：只列出该会话最近 10 个文件。这里使用完整 ID；`/resume 1` 的快捷序号不是日志命令参数。
- `--workspace`：显式选择其他工作区。省略时使用执行命令的目录。
- `--json logs`：供脚本读取，返回 `directory` 和 `files`。

这些查看操作只读本地目录，不调用模型。独立的 `ylc logs` 不加载模型配置、凭据或 MCP，配置损坏时仍能定位已有日志；因此它返回的 `enabled` 是 `null`，表示没有读取当前记录开关。交互中的 `/logs` 可以显示已经加载的开关。

## 文件在哪里

每个提交的任务一个文件，存放在该任务工作区：

```text
.harness/
  logs/
    完整会话ID/
      UTC时间-随机ID.md
```

例如在 `D:\code\demo` 执行 `ylc`，日志就在 `D:\code\demo\.harness\logs`，与安装目录无关。文件名使用 UTC 时间，文内也明确标注 UTC。

`/resume` 或 `ylc resume` 后提交新任务，会在原会话目录新增文件。`/rewind` 保留当前会话 ID 和旧日志；回退后提交的任务仍新增文件，可追溯回退前的过程。会话历史保存在 `.harness/sessions`，日志本身不承担恢复和回滚。

普通非交互任务在完成时显示日志路径，`--quiet` 可抑制此提示。`ylc --json run "你的任务"` 的任务报告包含 `traceFile`；关闭记录或未能创建日志时为 `null`。文件存在不代表记录完整，应检查文件末尾的任务状态或停止记录提示。

## 会记录什么

重点看同一编号的“HTTP 请求报文”和“HTTP 响应报文”：前者是发给厂商的正文，后者是收到的正文；旁边的“模型请求/回复”记录来源、模型、时间、用量和处理结果。

| 你要排查什么 | 日志提供什么 |
| --- | --- |
| 到底发了哪些提示词 | 适配器序列化后的请求 JSON，包括系统提示、历史、工具定义、参数和实际发送的工具结果 |
| 请求走了哪个接口 | HTTP 方法、去掉用户信息和查询参数的地址、协议字段、流式标记 |
| 厂商到底返回了什么 | HTTP 状态、响应类型、收到的 JSON 或 SSE 文本；包含工具调用、用量、错误详情及未被通用模型抽取的扩展字段 |
| 重试了几次 | 每次外层模型调用有独立编号；适配器内部重试显示 HTTP 尝试编号；主模型、审核模型、摘要模型分别标为 agent、reviewer、summarizer |
| 工具做了什么 | 工具开始、参数、完成/失败与结果摘要；结果随后发给模型时，可以在请求报文里查看实际发送内容 |
| 流式中断了什么 | 已捕获的 SSE 片段与读取状态，以及后续模型请求失败事件；不会把片段冒充完整回复 |

目前内置原生 HTTP 适配器和 LangChain4j OpenAI 适配器已接入：Chat、Responses、Anthropic、Gemini、Azure 及兼容这些协议的自定义地址。第三方 SPI 模型如果未接入 HTTP 观察器，会明确标注“逻辑请求备用记录”，只能看到内部消息和解析后的结果。

这里保存的是**脱敏后的 HTTP 正文**，不是网络数据包。JSON 保留字段和值，重新缩进后保存；空白和字段顺序不用于逐字节对照。SSE 在解析前采集，保留已读到的事件头、数据行和结束标记。程序可能在协议结束标记处停止读取，不承诺收集服务器之后额外发送的数据。

日志只保存厂商实际返回的内容，不生成或推断模型内部思考。若接口返回推理摘要或不透明扩展字段，会像其他协议字段一样记录。请求头、响应头全集、URL 查询参数、完整连接配置均不保存；响应仅摘取 Content-Type。用量仍以厂商返回为准，未报告时不能推算账单。

## 重复内容只存一份，怎么读

新版日志（`format_version: 2`）直接在 `body` 原字段展示首次内容，**不会第一次就把提示词替换成占位符**。只有后续相同内容才显示 `[引用 wire-1]`。

| 字段 | 含义 |
| --- | --- |
| body | 当前报文结构，首次出现的提示词、工具定义和返回内容直接显示在对应字段 |
| references | 仅列重复内容的 JSON 路径与引用编号；没有重复内容时是空对象 |
| content_locations | 本节首次记录的编号与正文路径，例如 `wire-1 → /messages/0/content`；只保存位置，不重复保存正文 |

报文下面的“重复内容定位”会写明原文在哪一条 HTTP 请求或响应中、哪次尝试、哪个 `body` 字段。HTTP 报文不再生成看起来像空内容的 HTML 锚点。

例如第一次请求的 `messages[0].content` 直接显示系统提示词；第二次才显示 `[引用 wire-1]`，并注明 `wire-1 → HTTP 请求报文 #1（尝试 1），body/messages/0/content`。索引为空代表没有新增内容或没有重复内容，不表示报文为空。

**旧日志也没有因为引用而丢失正文。** 旧版 `body.content` 中的 `[引用 wire-1]` 对应本文件 `new_content` 下的 `wire-1` 原文；`<a id="wire-1"></a>` 只是跳转标记，不是提示词。下方还原脚本兼容两种格式，无需手工翻找。已生成的旧日志保持原样，新格式从更新后重新启动的下一次任务开始生效。

提示词文本、工具参数、工具定义和长文本先脱敏再去重。每个任务文件自成一体，引用不会指向其他文件。短协议字段仍保留，便于看清请求结构；这不是把整个重复请求省略掉。

占位**只减少本地日志重复，不减少模型输入 token**。真正发出的请求完全不受日志去重影响，也不会为了生成日志额外调用模型。

## 想直接看到展开后的完整报文

仓库提供只读脚本，可以把本文件的引用还原。用 Python 运行以下命令，路径替换为实际位置；脚本可以在任意工作目录执行：

~~~powershell
python "E:\github\YLCoder-harness\scripts\read_model_trace.py" "D:\code\你的项目\.harness\logs\会话ID\任务日志.md" --request 2 --kind request
python "E:\github\YLCoder-harness\scripts\read_model_trace.py" "D:\code\你的项目\.harness\logs\会话ID\任务日志.md" --request 2 --kind response
~~~

省略筛选参数会展开全部请求和响应。JSON 显示为缩进文本，SSE 展开为多行文本；缺失引用或损坏的日志会报错。该脚本随源码提供，当前全局安装器不安装 Python 工具。正常阅读 Markdown 不需要 Python。

## 展示长度和关闭方式

私有配置可包含：

~~~yaml
trace:
  enabled: true
  tool-result-max-chars: 2000
~~~

- enabled 默认 true；设 false 并重新启动后不再创建新日志，旧文件仍可查看。
- tool-result-max-chars 默认 2,000，可设 128–32,000，控制工具过程及错误的简短预览。**它不再裁短 HTTP 报文中的工具结果或模型正文**。
- 单次 HTTP 响应最多捕获 8 MiB 字节；报文落盘另有 8,388,608 个 Java UTF-16 单元保护上限。超过会明确标注截断，不能还原完整报文。
- 第三方 SPI 的逻辑补录沿用单段 1,048,576 字符和工具预览限制。
- 每个任务文件最多 32 MiB。达到上限会提示并写停止记录标记，后续事件不再记录；任务仍继续。报文去重索引最多 65,536 条，满后新正文直接保留；旧式逻辑内容索引有独立保护上限。

工具或上下文管理如果在发送前已裁剪结果，日志只能记录实际发送的内容，无法补回上游丢弃的部分。流式中断可保留已读取片段；非流式 HTTP 客户端若在完整正文返回前失败，可能没有正文可记录，此时会显示未完成状态。

没有自动按天清理或跨文件去重。日志目录有自己的 .gitignore，默认 Git 操作会忽略新日志，已经跟踪的文件不受此规则保护。清理前先结束正在写日志的任务。

## 凭据和故障边界

配置中的模型/审核密钥、额外请求头值，以及常见凭据字段和格式都会遮盖。先脱敏再去重；相同秘密不会因为引用而绕开脱敏。未知的项目秘密无法保证全部识别，日志仍包含代码和对话，应保留在本地，分享前检查。

日志目录会检查链接/junction、文件身份和异常外部追加。目录不可写、路径重定向或落盘失败时，只提示一次并停止本次记录，不改到其他目录保存，编程任务继续执行。关闭记录时不会创建日志文件。

/logs 和 ylc logs 只查询本地路径，不把日志内容发送给模型。默认的项目列目录和搜索跳过 .harness；用户明确请求读取日志时仍按文件工具权限处理。

旧日志不能补回当时未采集的 HTTP 正文。本次格式从更新后新提交的任务开始生效，需要退出旧 ylc 进程再启动。日志会增加本地脱敏、缓冲和磁盘写入开销，目前没有单独测量该开销，不宣称性能零损耗。

## 本地验证

先打包，再运行：

~~~shell
python scripts/smoke_execution_trace.py
~~~

该脚本从打包 CLI 发起真实 HTTP 请求到 localhost，将日志引用展开，与模拟服务实际收到的请求和发出的响应逐项比较；同时检查工具、恢复/回退、审核、重试、部分回复失败、关闭记录与写入失败。独立 home 与工作区不加载真实凭据，不请求真实厂商。验收结果见 [报文日志测试报告](MODEL_WIRE_LOG_REPORT.md)，早期功能记录见 [执行日志验证记录](EXECUTION_LOGS_VERIFICATION.md)。

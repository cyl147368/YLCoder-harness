# “看一下当前项目”反复裁剪：修复与验证报告

验证日期：2026-11-06（北京时间）

## 先看结果

**这是程序的处理策略有缺陷，简单查看项目不应该默认变成全库审计，也不应该因为用户只说了两三轮话，就无法整理大量旧工具结果。**

这次修了读取策略、摘要边界和提示计数，并用修复前后的两个实际运行包做了对照。在测试中，恢复大历史后的 5 次本地裁剪降到了 0 次；新会话查看 1,200 个源码文件的示例项目，最大请求的消息上下文减少了约 42%～44%。

程序已经更新到本机全局安装的 `ylc`。退出正在运行的旧进程，再启动即可生效，已有厂商配置保留。

## 为什么简单任务会这样

没有拿到用户那次 86,325 token 运行的完整请求日志，所以不能断言其中每一部分占了多少。以下问题已经在源码和复现测试中确认：

| 已确认的问题 | 会造成什么 | 这次怎么改 |
|---|---|---|
| “看一下”没有被识别为分析任务，“看下”却可以 | 常见表达会进入更宽泛的默认模式 | 两种表达都进入只读分析模式；简单概览先定位、抽样，再给结论 |
| 仓库地图只展示几十个文件，却先读取了所有符合条件的源码正文 | 本地扫描做了很多无用功 | 空查询先收集路径，只解析选中展示文件的声明，默认 20 个；未变化的文件可复用缓存 |
| 默认一次读 300 行 | README、构建文件和源码很容易带回过多内容 | 默认改为 100 行；返回后续起始行，需要时再明确读取 |
| 两到四轮用户消息里积累了大量工具结果，却仍被整体当作“近期内容” | 没有可用的摘要边界，只能反复裁剪 | 根据实际 token 预算选择已完成的工具组，不再只看用户说了几轮 |
| 摘要确实变短了，但没有达到理想比例就被丢弃 | 有用摘要不能保存，后面继续重复处理 | 保留有效缩小请求的摘要；理想比例用于优化，真实预算仍作为硬约束 |
| 先判断是否需要摘要，再应用已有工具预览上限 | 本来用预览就能控制的大小，也可能触发额外摘要 | 先应用单条工具预览，再判断是否需要摘要 |
| 复用摘要后，仍按完整历史显示“整理前”的大小；每次请求都重复提示 | 看上去像每一步都又裁剪了一遍 | 改为统计本次真正准备发送的上下文；复用摘要不重复刷屏，详细指标仍进入请求日志 |

用户原始要求继续保留。工具调用和对应结果按完整组处理，不能拆散；保存的完整会话与发给模型的精简版本仍然分开。

## 修复前后，实际差了多少

两个版本使用相同的测试仓库、配置和固定工具步骤：获取地图，读取 README、构建文件和一份源码，最后回答。每组都是 5 次主模型请求、4 次工具调用。

**下表比较的是主请求中消息上下文的本地估算值，不是厂商账单。** 包含消息和调用元数据；工具定义另行从配置的 50,000 token 预算中扣除。因为新版本识别到了只读分析模式，工具集合也相应变小，两个版本的可用消息预算略有不同。

| 场景 | 接口 | 修复前最大消息上下文 | 修复后最大消息上下文 | 减少 | 本地裁剪次数：前 → 后 |
|---|---|---:|---:|---:|---:|
| 新会话查看 1,200 个源码文件的项目 | Chat | 7,404 | 4,130 | 44.22% | 0 → 0 |
| 同上 | Responses | 7,802 | 4,524 | 42.01% | 0 → 0 |
| 恢复约 8.5 万 token 的旧工具历史，再查看项目 | Chat | 48,801 | 28,410 | 41.78% | 5 → 0 |
| 同上 | Responses | 48,801 | 28,804 | 40.98% | 5 → 0 |

恢复大历史时，新版本第一次把消息上下文从约 85,152 整理到 24,655 token，后续复用摘要。随着这次查看任务继续读取必要内容，最后一条请求增长到表中的 28,410 或 28,804。界面只提示了一次新的整理结果。

这里的“一次整理”**不等于只调用一次摘要模型**：本例旧资料较多，分块处理一共发了 5 次摘要请求。上表没有把这部分输入输出费用算成节省，也没有计算缓存折扣。因此，不能把 42%～44% 的消息缩小比例当作账单降幅。

另外，仓库地图的单独测试准备了 120 个源码文件：首次默认概览只打开 20 个源码，紧接着再次查询打开 0 个，仍能按指定关键词找到未在默认列表展示的文件。

| 检查 | 结果 | 能说明什么 |

| 原有上下文完整流程回归 | Chat / Responses × 摘要正常 / 摘要异常，共 4 组通过 | 恢复摘要、摘要失败冷却、历史查找、工具原文找回、同 ID 回退仍可工作 |

16 个跳过项中，14 项需要当前 Windows 账号没有获得的符号链接创建权限，2 项需要 POSIX 权限支持。

**边界也说清楚：** 模型服务全部由本机模拟，真正运行的是打包 CLI 和工具。固定回复保证两个版本可比，但不能证明真实模型一定会严格遵守“先概览再深入”的指引，也没有测出真实厂商延迟或完整账单。若摘要服务失败、厂商回放信息限制了摘要边界，或单组必留内容本身超出预算，仍可能本地裁剪或明确报预算不足；本次没有承诺永不裁剪。

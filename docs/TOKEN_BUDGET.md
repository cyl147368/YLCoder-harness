# 本地分词器预算统计

在 interactive/run/resume 命令上选择 `--token-counter cl100k` 或 `--token-counter o200k`，也可在可信 YAML 中设置 `agent.token-counter`。`utf16` 仍为兼容性默认值。未知/null 值在模型调用或 MCP 启动之前失败。选定计数器同时作用于注册 schema（包括 MCP）和对话消息，不改变输出 token 上限。

```shell
ylc run "修复失败的解析器" --token-counter o200k --context-budget 12000
```

核心公开 `InputTokenCounter`，可提供其他本地统计策略，不让厂商中立循环耦合 JSON 库或厂商分词器。CLI 使用随包 Jtokkit 1.1.0、无特殊 token 解释的普通分词，以及递归排序的规范 JSON。每条完整消息包括角色、工具身份、调用 JSON 和不透明厂商元数据。工具定义包含说明和原始 schema。添加 16 token 包络预留量、每条消息八 token；非空工具集预留 64 token，再加每个定义八 token。这些是显式本地预留量，不宣称精确模拟厂商内部消息框架。

各记录独立编码后求和。它们执行选定的本地统计预算，不是精确厂商传输/账单 token 上限。匹配编码和预留量可改善 UTF-16 低估，尤其是 CJK；Anthropic/Gemini/自定义厂商可能使用不同分词器或编码。不会静默推断厂商。请为厂商转换、内部聊天模板和输出预留空间，并参考真实评测中的实际用量。

压缩用选定计数器测量候选内容，不再假定四个字符节省一个 token。裁剪文本时 BPE 计数可能非单调，因此只保留实测在预算内的候选。系统/原始/最近用户文本、调用参数和签名绝不裁剪；过大的必需输入在本地失败。具有消息级或旧式调用级回放元数据的消息保留完整可见文本，以保持原始回放一致。完整的可选历史块仍可能被移除。文本裁剪尊重 UTF-16 代理对。已有完整工具循环保护仍生效。

为提高速度，不可变消息身份缓存计数。FIFO 缓存最多 256 项和 1,048,576 个序列化 UTF-16 单元；它保存引用/计数，不额外保存源码 JSON。过大记录不缓存。注册表编码每进程惰性加载一次。缓存淘汰只改变性能，不改变计数；缓存仅持续一次智能体调用，不持久化密钥。

验收覆盖必需 CJK 指令在模型调用前失败、有界 CJK/emoji 工具结果、独立序列化数组计数、不透明元数据保留、schema 开销、缓存淘汰和配置/CLI 拒绝。带版本的上下文基准接受 `--token-counter cl100k` 和 `--token-counter o200k`，复现统计、保留和热缓存压缩时间。冷分词器启动和真实模型时间不在此压缩测量范围内。

`python scripts/smoke_token_budget.py` 使用实际 shaded jar 和 localhost 服务验证两种 CLI 模式、旧式兼容性，以及过大的必需 CJK 恢复在无 HTTP 请求时失败。
